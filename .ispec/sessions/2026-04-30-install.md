## Trigger

Need to retrofit ispec onto another project from a fresh Claude Code session in that project's checkout. That requires ispec's workflow skills and the `ispec-lint` binary to be discoverable globally rather than scoped to ispec's own working tree. Currently the skills live at `<ispec-checkout>/.claude/skills/` (project-scoped to ispec) and the binary lives at `<ispec-checkout>/ispec-lint` (not on PATH).

## Pre-decisions

- Symlinks rather than copy or `go install` for v0.1 (recorded as [[ADR-0003]]). Fast feedback during ispec's own iteration; can supersede with a real distribution path once ispec stabilizes.
- Trim path-coupled references in skill files rather than introduce a shared "ispec docs" install location. Smaller change; avoids pre-committing to a distribution model.

## Contract

In ispec:
- New REQ-3 (cross-project-usability)
- New F-3 (install-pathway, targets REQ-3)
- New ADR-0003 (install-via-symlinks)
- F-2 spec-session-skill: SKILL.md amended to remove a path-coupled reference to `docs/design.md`. F-2's card body is unchanged; the fix is at implementation level.
- Drive-by: same path-coupling scan applied to bootstrap, retrofit, session-close, defer skill files. Their feature cards are deferred and not authored in this session, so the fixes ride along without amendment cards.

Out of scope (deferred):
- Capturing bootstrap, retrofit, session-close, defer as feature cards.
- Versioned distribution (`go install`, package managers, version pinning per consuming project).
- Auto-rebuild of the lint binary on source changes.
- Multi-user / system-wide install.

## Discoveries during the session

- Only one of the `docs/` references in skill files is genuinely path-coupled to ispec (spec-session line 137, removed). The others — retrofit's `**README.md, OPS.md, DESIGN.md, NOTES.md, docs/**` and session-close's `docs/user-manual.md` etc. — are correctly relative to the project that *adopts* ispec, not ispec itself. The drive-by audit found nothing else to fix.
- `make install` is idempotent on existing entries (skips with a `skipping ... (already exists)` message). Tested by running it twice; second invocation correctly no-op'd.
- The Makefile's `.DEFAULT_GOAL := help` makes a bare `make` show usage rather than silently building, which is friendlier for new users.
- Verified with `make install SKILLS_DST=/tmp/... BIN_DST=/tmp/...` that the install respects custom destinations on both install and uninstall paths.
